# 开发约定

## 结构与推进顺序

核心通信放在独立 Rust crate，使用异步 HTTP/WebSocket、结构化错误和可取消订阅。
应用层管理连接、持久化和界面状态。Slint 在界面线程接收状态、发出操作意图。

先验证协议与连接生命周期，再用实时表格、图表和 Android 输入滚动验证界面方案，
最后完成页面并按基线逐项验收。

## Rust 约束

手写源码、测试及构建脚本使用 `Result`、`Option` 和显式错误传播。
对 `unwrap`、`expect`、显式 panic 和 unsafe 设置静态检查；必须使用时，
在最小范围说明必要性、成立条件及调用契约。第三方库通过其安全接口使用，
自动生成代码与手写代码分别设置检查范围。

## 验证环境

测试服务绑定回环地址并使用独立临时目录。实际核心测试启动测试进程，
使用独立配置、控制端口及测试数据，仅结束自己创建的进程。
日常正在运行的 mihomo 默认仅用于必要的只读检查。

首批目标为 Linux x64（Wayland/X11）、Windows x64、macOS arm64/x64、
Android arm64。构建检查和实际运行检查分别记录；记录工具链、设备与结果。

Release 配置使用 `lto = true`、`opt-level = "z"`、`strip = true`、
`codegen-units = 1`。以实际产物和负载测试指导体积、内存与响应速度优化。

## Git 与文档

按可验证阶段提交，保留原始模板提交。提交前运行相关格式、静态检查与测试。
文档描述现有功能、使用方法和必要的开发信息。上游版本与功能映射见
[upstream-baseline.md](upstream-baseline.md)。
