# UI 实现与对照

基线：MetaCubeXD `v1.273.1`，提交 `8bbc8f58fef71148a94fb5c0ff808f79b057337d`。
核心：MetaCubeX 官方 Mihomo。

## 当前可运行界面

| 页面 | 已接通的功能 |
| --- | --- |
| 连接 | 地址、名称、Secret；连接检查；保存、编辑、删除及切换；恢复上次选择；鉴权和连接错误提示 |
| 导航 | 桌面侧栏收放；窄屏底部导航及更多菜单；运行模式切换；刷新；语言及明暗主题 |
| 概览 | 六项实时指标；流量、内存、连接数量曲线；上传/下载分布、网络类型、代理用量 |
| 代理 | 策略组和代理集；节点选择、恢复自动选择；卡片/列表、折叠、搜索、自然/名称/延迟排序；单节点、组与代理集测速、批量测速及取消；代理集更新 |
| 规则 | 规则/规则集；搜索、状态筛选、列排序、启用开关、命中信息；规则集更新 |
| 连接 | 活动/关闭历史；虚拟滚动、横向滚动、搜索、协议筛选、按属性归类、列排序、暂停；详情、单条/全部关闭；CSV/JSON 导出 |
| 流量 | 按小时记录连接增量；按域名、进程、来源、策略组汇总；时间范围与保留天数；CSV/JSON 导出 |
| 日志 | 实时订阅、级别、搜索、列排序、暂停、清空、数量限制、详情；CSV/JSON 导出 |
| 配置 | 运行参数、端口、TUN 参数；配置重载、远程配置加载、核心重启/更新、托管面板更新、GEO 更新、缓存清理；DNS 查询；面板设置及备份导入导出 |

输入型运行参数可按 Enter 提交，也可点击编辑后出现的保存按钮。
代理组标题显示核心返回的 `icon`，支持 HTTP(S) 图片和内嵌 SVG；内嵌 SVG 使用主题强调色。
图标异步加载并共享内存缓存，最多保留 128 个当前配置中的图标，单个下载上限为 1 MiB，失败后间隔 60 秒重试。
图标请求使用独立客户端：macOS／Windows 默认检测系统代理，Linux 读取 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 和 `NO_PROXY` 环境变量；Android 跟随系统网络和 VPN 路由。
节点卡片右上角的测速按钮可单独测试该节点，延迟显示在卡片下方。
图标按钮提供悬浮提示；成功提示在 4 秒后收起。图表的颜色与下方图例一一对应。
表格点击列标题在升序与降序之间切换，箭头和高亮显示当前排序；表头获得焦点后也可按空格或 Enter 切换。
速度、流量和计数按原始数值比较，时间按实际时刻比较；实时刷新沿用当前排序。
维护操作的确认窗口绑定发起时的会话。切换连接后，旧请求、订阅和测速结果失效。
代理选择与恢复自动选择按设置关闭经过对应组的连接；模式切换按设置关闭当前核心的连接。

## 应用状态

- Slint 在界面线程渲染模型；Tokio 的两个工作线程执行异步请求与订阅。
- 后台事件通过有界队列传入界面，界面每 50ms 接收、最多每 100ms 提交一次数据变化。
- 只更新受到事件影响的页面。表格与代理组保留已有模型，逐行更新变动内容。
- 普通 HTTP 刷新使用请求序号，操作前发出的旧刷新结果会被丢弃。
- 日志和关闭连接历史有数量限制。暂停保留可筛选、排序的显示快照，实时采集继续运行。
- 存储工作串行执行；文件原子替换。退出时等待已排队的写入并传播存储错误。
- 统计历史按后端隔离，初次连接的快照建立计数基准，随后累计增量。

数据目录：

| 平台 | 位置 |
| --- | --- |
| Linux | `$XDG_DATA_HOME/nekodash`，默认 `~/.local/share/nekodash` |
| Windows | `%LOCALAPPDATA%/nekodash` |
| macOS | `~/Library/Application Support/nekodash` |
| Android | 应用内部数据目录下的 `nekodash` |

桌面开发可用 `NEKODASH_DATA_DIR` 指定独立目录。
导出时在窗口中填写目标路径，默认位置是数据目录下的 `exports`。
语言资源取自固定基线，许可文件在 `assets/i18n/LICENSE`。

## 下一轮逐项对照

当前是首轮可运行实现。完整的布局与交互验收仍需继续，重点为：

1. 代理页面其余展示模式、卡片密度、组预览、质量推荐及测试历史。
2. 连接表列显隐/顺序、分组标题与展开、分页、快速筛选、来源标签与反向 DNS；详情窗口的字段布局。
3. 规则的类型/策略筛选和排序选项；日志标签、分组、列设置及复制交互。
4. 概览 IP 信息、可达性测试与网络拓扑；统计趋势、排行、钻取及自定义时间段。
5. DNS 设置表单、设置备份与文件选择交互、快捷键、其余外观偏好及多语言细节。
6. Windows、macOS、Android 的原生输入、滚动、生命周期及包体实测；Linux 图形后端的性能与关闭行为。

按页面记录上游入口、操作、预期和实际结果，完成一项后更新此表。页面存在和
协议接口齐全不作为全部对齐的判定条件。

## 可重复的 UI 验证

```sh
SLINT_EMIT_DEBUG_INFO=1 cargo build --features slint/mcp --locked
python3 scripts/ui_smoke.py --mihomo /path/to/mihomo --output target/ui-smoke/desktop
python3 scripts/ui_smoke.py --mihomo /path/to/mihomo --size 390x844 --output target/ui-smoke/mobile
```

脚本启动自己的临时核心和回环连接，完成后清理对应子进程。
它验证错误 Secret 后重试、连接、页面导航、节点选择、普通及 provider 节点独立测速、
成功提示自动收起、布局边界、规则启用开关、表头鼠标及键盘排序、
横向滚动后的排序、实时数据重排及排序后的单条连接关闭，
并保存截图和运行日志。`NEKODASH_WINDOW_SIZE=390x844` 可用于调试构建的窗口尺寸检查。

Android 使用应用库入口和内部数据目录。配置已写入 `Cargo.toml`，可用
`cargo apk build --lib --target aarch64-linux-android` 构建；设置 Android SDK/NDK 后执行。
设备运行结果单独记入验证记录。
